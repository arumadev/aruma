# توافق قاعدة المستندات: الإصدار 0.4

- **الحالة:** بدأه F4-A3 بقيود البث (2026-10-27)، وتضيف المسارات الأخرى أقسامها.
- **المرجع السلوكي:** الإنتاج حيث سُجّل (`test/oracle/documents/corpus`)، ثم مصادر الـ SDK ووثائق Google، ثم المحاكي. والفروق المسجَّلة على الإنتاج في `parity-exceptions.json` بأسبابها.
- **التصنيف:** **قيد** أشد من Firebase عمدًا، بمصدره في ADR. والقيود قابلة للضبط تحت `documents.limits` (`docs/configuration.md`).

## قيود البث (F4-A3)

حدود Listen وWrite، وكل منها أشد من الإنتاج أو لا نظير موثّقًا له فيه. ولا إسقاط صامت: كل تجاوز يصل العميل برمز، ويُعدّ في `documents_stream_overflows_total{limit}` أو `documents_stream_closes_total{reason}`، وله سطر في السجل.

| القيد | السلوك عندنا | الإنتاج | المصدر |
|---|---|---|---|
| `streams_per_project` (10000) | بث Listen أو Write فوقه يُرفض عند أول رسالة بـ `RESOURCE_EXHAUSTED` «Too many streams are open on this project.» | لا حد موثّق لعدد البث | ADR-026 §3 |
| `streams_per_ip` (500) | كل بث من عنوان واحد، Listen وWrite وبث الخادم معًا، فوقه يُرفض بـ `RESOURCE_EXHAUSTED` | لا حد موثّق | ADR-026 §3، ADR-027 §3.2 |
| `targets_per_stream` (1000) | هدف فوقه: `REMOVE` له وحده بسبب `RESOURCE_EXHAUSTED`، والبث باقٍ | لا حد موثّق (OF «Could not verify» 7)؛ مؤقت | ADR-026 §3 |
| `snapshot_rows` (1,000,000) | هدف تمر قراءته (اللقطة، الاستئناف، ملء نافذة limit) بأكثر منه: `REMOVE` له وحده بسبب `RESOURCE_EXHAUSTED` | لا حد موثّق | ADR-026 §3 |
| `stream_outbox_bytes` (64 MiB) | عميل يترك ما لم يُرسل ممتلئًا مدة `stream_write_stall` يُغلق بثه. ولأن آخر كتابة عالقة على نافذة العميل، يقطعها الإغلاق فيرى العميل إعادة ضبط البث (`INTERNAL`) لا `RESOURCE_EXHAUSTED`، ويعيد الاتصال برموز استئنافه | لا حد موثّق | ADR-026 §3 |
| `stream_lag_events` (4096) | بث تأخر عن الموزّع: RESET لأهدافه ولقطة جديدة | لا حد موثّق؛ مؤقت | ADR-026 §1.4، §3 |
| `stream_idle` (5 دقائق) | Listen بلا هدف، أو Write بلا طلب، دون رسالة: يُغلق بـ `UNAVAILABLE` | لا حد موثّق | ADR-026 §3، ADR-027 §3.2 |
| `stream_first_message` (10 ثوانٍ) | بث لم يرسل أول رسالة: `DEADLINE_EXCEEDED` قبل أي عمل | لا حد موثّق | ADR-027 §3.2 |
| انتهاء الرمز | بث يُغلق بـ `UNAUTHENTICATED` عند `exp` رمز المستخدم أو حساب الخدمة | الرمز في ترويسات الفتح وحدها ولا يُجدَّد داخل البث (CL §3)؛ غير مسجَّل | ADR-026 §4، ADR-029 §3.8 |
| إلغاء المستخدم | مستخدم عُطّل أو حُذف أو أُبطلت رموزه: بثه يُغلق فورًا بـ `UNAUTHENTICATED`، وإعادة فتحه بالرمز نفسه تُرفض. ورمز المستخدم يُتحقق منه عند فتح البث وحده؛ وحتى F5 لا يصل المستخدم إلى البيانات إلا مع `dev_open_rules` | غير مسجَّل في الإنتاج | ADR-026 §4 |
| فقد قفل النسخة | كل Listen وWrite يُغلق بـ `UNAVAILABLE`، ولا يُقبل بث جديد حتى يُستعاد القفل بموزّع جديد | لا نظير (نسخة واحدة على Postgres) | ADR-026 §5، ADR-024 §7 |
