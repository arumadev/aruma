# Client configuration files and SDK validation

Research notes behind ADR-007. Gathered 2026-10-17 from public sources only (official docs and the public SDK repositories). Each point links to where it was checked.

## API key

- Android Installations: `apiKey` must match `\AA[\w-]{38}\z`, i.e. `A` + 38 chars of `[A-Za-z0-9_-]`. A mismatch throws `IllegalArgumentException` lazily on `getId()`/`getToken()`. [Utils.java](https://github.com/firebase/firebase-android-sdk/blob/main/firebase-installations/src/main/java/com/google/firebase/installations/Utils.java)
- iOS Installations: exactly 39 characters, starts with `A`, alphanumerics plus `-` and `_`. A mismatch raises an NSException. Installations is instantiated eagerly, so the crash happens during `FirebaseApp.configure()` when it is linked. [FIRInstallations.m](https://github.com/firebase/firebase-ios-sdk/blob/main/FirebaseInstallations/Source/Library/FIRInstallations.m)
- Web: no format check. Installations requires only non-empty `projectId`, `apiKey` and `appId`. [extract-app-config.ts](https://github.com/firebase/firebase-js-sdk/blob/main/packages/installations/src/helpers/extract-app-config.ts)
- **No SDK checks the `AIza` prefix.** A private prefix that keeps `A` + 38 chars of `[A-Za-z0-9_-]` is safe.

## App ID `1:<project_number>:<platform>:<hex>`

- iOS `validateAppID`: for version `1` it requires exactly 4 colon-separated parts, platform literally `ios` (macOS too), and a hex-only tail parsed with `scanHexLongLong`. There is no length check. Failure raises an NSException. [FIRApp.m](https://github.com/firebase/firebase-ios-sdk/blob/main/FirebaseCore/Sources/FIRApp.m)
- Android only checks that the ID contains `:`. Web does not check it.
- The docs' examples use 16 hex characters for iOS and Android and 22 for web. [learn-more](https://firebase.google.com/docs/projects/learn-more)
- 16 hex characters fit `scanHexLongLong` exactly. Overflow behaviour beyond 16 is unconfirmed, so Aruma uses 16 everywhere.

## Web `firebaseConfig`

- Fields: `apiKey`, `authDomain`, `databaseURL`, `projectId`, `storageBucket`, `messagingSenderId`, `appId`, `measurementId` (optional). [learn-more](https://firebase.google.com/docs/web/learn-more)
- `initializeApp` checks only the app name, that options are present, and duplicate apps. It makes no network calls. [api.ts](https://github.com/firebase/firebase-js-sdk/blob/main/packages/app/src/api.ts)
- The Management API `WebAppConfig` adds `projectNumber`, `locationId` and `version`. [getConfig](https://firebase.google.com/docs/reference/firebase-management/rest/v1beta1/projects.webApps/getConfig)

## Android `google-services.json`

- Required by the Gradle plugin, otherwise a `GradleException`:
  - `project_info.project_number`
  - `project_info.project_id`
  - a `client` whose `package_name` equals the applicationId
  - a non-empty `mobilesdk_app_id`
  - at least one `api_key[].current_key`
  - [GoogleServicesTask.kt](https://github.com/google/play-services-plugins/blob/main/google-services-plugin/src/main/kotlin/com/google/gms/googleservices/GoogleServicesTask.kt)
- Optional: `storage_bucket` becomes `google_storage_bucket`, and `firebase_url` becomes `firebase_database_url`.
- Output resources: `gcm_defaultSenderId` (project_number), `google_app_id`, `google_api_key`, `google_crash_reporting_api_key` and `project_id`. [plugin guide](https://developers.google.com/android/guides/google-services-plugin)
- The plugin picks the first client whose `package_name` matches, so one file holds every Android app of the project.
- Latest plugin: `com.google.gms:google-services` 4.5.0 (2026-06-16).
- Runtime: `FirebaseOptions` only checks that apiKey and applicationId are non-empty. [FirebaseOptions.java](https://github.com/firebase/firebase-android-sdk/blob/main/firebase-common/src/main/java/com/google/firebase/FirebaseOptions.java)

## iOS `GoogleService-Info.plist`

- Strings: `API_KEY`, `GCM_SENDER_ID`, `PLIST_VERSION` ("1"), `BUNDLE_ID`, `PROJECT_ID`, `STORAGE_BUCKET`, `GOOGLE_APP_ID`, `DATABASE_URL`, `CLIENT_ID`, `REVERSED_CLIENT_ID`.
- Booleans: `IS_ADS_ENABLED`, `IS_ANALYTICS_ENABLED`, `IS_APPINVITE_ENABLED`, `IS_GCM_ENABLED`, `IS_SIGNIN_ENABLED`.
- Reference file: [mock plist](https://raw.githubusercontent.com/firebase/quickstart-ios/main/mock-GoogleService-Info.plist)
- FirebaseCore reads `API_KEY`, `GOOGLE_APP_ID`, `GCM_SENDER_ID`, `DATABASE_URL`, `STORAGE_BUCKET`, `BUNDLE_ID` and `PROJECT_ID`. [FIROptions.m](https://github.com/firebase/firebase-ios-sdk/blob/main/FirebaseCore/Sources/FIROptions.m)
- A bundle ID mismatch only logs an error. It does not crash.

## Flutter `firebase_options.dart`

- Generated by the FlutterFire CLI. [template](https://github.com/invertase/flutterfire_cli/blob/main/packages/flutterfire_cli/lib/src/firebase/firebase_dart_configuration_write.dart)
- Structure: `class DefaultFirebaseOptions` with a `currentPlatform` getter, which returns `web` when `kIsWeb` and otherwise switches on `defaultTargetPlatform`. Each platform is a `static const FirebaseOptions`.
- Unconfigured platforms throw `UnsupportedError`.
- Fields are written in order and only when non-null: `apiKey, appId, messagingSenderId, projectId, authDomain, databaseURL, storageBucket, measurementId, ..., iosBundleId`.
- Required by `FirebaseOptions`: `apiKey`, `appId`, `messagingSenderId`, `projectId`. [firebase_options.dart](https://github.com/firebase/flutterfire/blob/main/packages/firebase_core/firebase_core_platform_interface/lib/src/firebase_options.dart)

## Service account key file

- Fields: `type: "service_account"`, `project_id`, `private_key_id`, `private_key` (PKCS#8 PEM, `BEGIN PRIVATE KEY`), `client_email`, `client_id`, `auth_uri`, `token_uri`, `auth_provider_x509_cert_url`, `client_x509_cert_url`, `universe_domain`. [IAM keys](https://cloud.google.com/iam/docs/keys-create-delete)
- RSA 2048.
- firebase-admin Node requires `project_id`, `private_key` and `client_email`, and parses the key. [credential-internal.ts](https://github.com/firebase/firebase-admin-node/blob/main/src/app/credential-internal.ts)

## adminSdkConfig

- Fields: `{projectId, databaseURL, storageBucket, locationId}`. The last three are deprecated. [getAdminSdkConfig](https://firebase.google.com/docs/reference/firebase-management/rest/v1beta1/projects/getAdminSdkConfig)

## Open, settled by smoke tests

- Closed-source binaries (Analytics, Crashlytics) may contact Google endpoints. They are out of scope for Phase 1, which tests initialisation only.
- Client SDK endpoints (Installations, Analytics) are not redirected by config files. That is the job of the client layers (Phase 5).
