# نموذج التهديد

يُحدَّث في كل مرحلة. آخر تحديث: المرحلة 2 (المصادقة)، بتاريخ 2026-10-18.

## ما نحميه

| الأصل | لماذا يهم |
|---|---|
| حسابات أصحاب المشاريع وجلساتهم | من يملكها يملك كل مشاريع صاحبها |
| رموز CLI ورموز حسابات الخدمة | وصول إداري دون متصفح |
| المفاتيح الخاصة لحسابات الخدمة | تسمح بسك رموز وصول. لا نخزّنها أصلًا |
| العزل بين المشاريع | مشروع A لا يرى B ولا يغيّره |
| المفتاح الرئيسي | منه تُشتق مفاتيح HMAC والتشفير |
| حسابات مستخدمي التطبيقات وجلساتهم (المرحلة 2) | من يملك حساب مستخدم يملك بياناته في تطبيق المطوّر |
| مفاتيح توقيع رموز الدخول لكل مشروع | من يملكها يسك رمز دخول لأي مستخدم. مشفّرة بالتشفير المغلّف |
| رموز التجديد ورموز البريد | تمنح جلسة أو تغيير كلمة مرور. تُخزَّن HMAC فقط |
| أسرار SMTP وGoogle وApple | تُستعمل باسم المطوّر عند مزوّد خارجي. مشفّرة، ولا تُعرض بعد الحفظ |

## حدود الثقة

1. **المتصفح ← اللوحة:** cookie جلسة، وCSRF، وCSP.
2. **أداة CLI أو خادم المطوّر ← Management API:** رمز Bearer، إما رمز CLI شخصي أو رمز حساب خدمة.
3. **تطبيقات المستخدمين ← واجهات الخدمات:** مفتاح API يعرّف المشروع فقط، ولا يمنح صلاحية. الهوية هي رمز الدخول أو رمز التجديد في الجسم. CORS مفتوح لهذه المسارات وحدها، دون cookies (ADR-014).
6. **خادم المطوّر ← Admin Auth API:** رمز وصول حساب خدمة من المشروع نفسه، أو رمز CLI لصاحبه. لا `Bearer owner` ولا مفتاح API ولا رمز مستخدم.
7. **المتصفح ← صفحات `authDomain`:** صفحة إجراءات البريد، ومعالج Google وApple وإطاره الخفي. CSP بالبصمات، و`frame-ancestors` بالنطاقات المصرّح بها.
8. **الخادم ← Google وApple وخادم SMTP:** مزوّدون خارجيون. يُتحقق من رموزهم بمفاتيحهم العامة و`aud` و`nonce`، ويُشترط TLS لـ SMTP.
4. **الخادم ← Postgres:** شبكة موثوقة أو محلية. والأسرار في القاعدة مجزّأة أو مشفّرة.
5. **الوكيل العكسي ← الخادم:** نثق بـ `X-Forwarded-For` من `trusted_proxies` فقط.

## التهديدات والتخفيف

| التهديد | التخفيف | الاختبار |
|---|---|---|
| سرقة جلسة صاحب المشروع | cookie محمي، وانتهاء خمول ومطلق، وإبطال عند تغيير كلمة المرور، وCSRF | AC-6، S-5 |
| تخمين كلمات المرور أو حشو بيانات الدخول | حد معدل لكل IP ولكل بريد، وتأخير متصاعد، وargon2id | S-6 |
| تعداد الحسابات | رسالة دخول واحدة، وتحقق وهمي يوحّد التوقيت | S-7 |
| السبق إلى التسجيل على خادم جديد مكشوف | رمز إعداد لمرة واحدة في السجل، والتسجيل مغلق | AC-4، S-1 |
| استخدام مفتاح API كهوية إدارية | المفتاح لا يمر عبر أي محقِّق إداري | S-10 |
| تغيير رقم المشروع أو معرّفه في الطلب للوصول إلى مشروع آخر | يُحل المشروع عند المدخل مع فحص الملكية، وكل استعلام يأخذ `project_number` | AC-19، العزل، فحص الاستعلامات |
| تعداد المشاريع | `NOT_FOUND` موحّد لما لا يملكه المستدعي | S-11 |
| نقل تطبيق أو مفتاح بين مشروعين بتعديل الطلب | المعرّفات الثابتة، و`project_number` من المسار المحلول لا من الجسم | العزل |
| تزوير رمز حساب خدمة | RS256 فقط، والتحقق بالمفتاح العام المسجّل، و`aud` و`exp` إلزاميان، وحد ساعة | AC-18، AC-28 |
| تسرّب سر في السجل أو القاعدة | حجب آلي بالنوع والاسم، وHMAC للرموز، ولا مفتاح خاص مخزَّن | X-7 |
| هجمات المتصفح على اللوحة (XSS، clickjacking) | CSP بلا `unsafe-inline` للسكربتات، و`frame-ancestors 'none'`، وReact يهرّب النصوص | S-9 |
| استنزاف الذاكرة بطلبات تجزيء كثيرة | حد تزامن argon2id، وحد معدل، وحد حجم الجسم | S-6، S-14 |
| خلط هويات المصادقة | محقِّق لكل هوية، وقائمة مسموحة لكل واجهة، واختبارات متقاطعة | AC-27، AC-28 |
| تزوير رمز دخول (`alg:none`، خلط الخوارزمية، حمولة معدّلة، `kid` مشروع آخر) | RS256 فقط، و`kid` إلزامي من مفاتيح المشروع نفسه، وفحص `iss` و`aud` و`exp` في الخادم والمكتبتين | التلاعب 1–7 |
| رمز مشروع على مشروع آخر، أو رمز بمُصدِر Google | مُصدِر لكل مشروع (ADR-004)، ورموز التجديد مقيّدة برقم المشروع | التلاعب 5–6 |
| جلسة مسروقة تبقى بعد تغيير كلمة المرور | `tokens_valid_after` إلى الثانية التالية، فلا تنجو جلسة من ثانية الإبطال (المراجعة H-3) | AC-A11، التلاعب 8 |
| custom token من مشروع آخر أو بمفتاح محذوف | التوقيع بمفتاح نشط لحساب خدمة من المشروع نفسه، و`aud` الرسمي، و`exp` ≤ ساعة | AC-A5، التلاعب 9–10 |
| تعداد بريد المستخدمين | حماية التعداد مفعّلة افتراضيًا: رمز دخول واحد، ونجاح صامت لإعادة التعيين، وقائمة طرق فارغة | AC-A4 |
| تخمين كلمات مرور المستخدمين | حد لكل عنوان، وتأخير متصاعد لكل مشروع وبريد، وargon2id بتزامن محدود. جداول الحدود تُخرج الأقدم عند امتلائها (المراجعة M-2) | التلاعب 21 |
| إغراق البريد أو استعماله للإزعاج | حد لكل مستلم ولكل عنوان ولكل مشروع | التلاعب 22 |
| إعادة استعمال رمز بريد أو التحويل إلى نطاق غير مصرّح | رمز 256 بت لمرة واحدة، وانتهاء، وربط بالمشروع، و`continueUrl` من النطاقات المصرّح بها فقط، ولا إجراء عند فتح الرابط (GET) | AC-A19، التلاعب 11–13 |
| الاستيلاء على حساب ببريد غير مؤكد ثم دخول صاحبه الحقيقي بـ Google | حين يؤكد المزوّد البريد تُحذف كلمة المرور والمزوّدون الآخرون وتُبطل الجلسات، وتسقط رموز تغيير البريد السابقة (المراجعة H-2) | اختبارات IdP |
| ربط كلمة مرور بحساب قائم عبر `signUp` برمز قديم | الربط للمستخدم المجهول فقط، وغيره `PROVIDER_ALREADY_LINKED` (المراجعة H-1) | `auth_review_test.go` |
| `state` معاد أو مبدّل، و`nonce` خاطئ في دخول Google وApple | جلسة لمرة واحدة مربوطة بـ `sessionId`، وPKCE لـ Google، و`nonce` إلزامي | التلاعب 14–16 |
| حقول إدارية من العميل | تُتجاهل في نقاط العميل (`customAttributes` و`disabled` و`localId`)، و`returnOobLink` مرفوض | التلاعب 17 |
| تعطيل التحقق في خادم المطوّر بمتغير المحاكي | مكتبتا Aruma ترفضان البدء مع `FIREBASE_AUTH_EMULATOR_HOST`، وترفضان http لغير loopback ونطاقات Google والتحويلات | ADR-013 |
| تسرّب سر خام في القاعدة أو السجل | HMAC للرموز، وتشفير مغلّف للمفاتيح والأسرار وصندوق البريد الصادر | التلاعب 20 |

## خارج النطاق حتى المرحلة 2

- الهاتف وMFA والدخول برابط البريد (v1.x)، وtenants.
- حدود المعدل في ذاكرة الخادم: تبدأ من الصفر عند إعادة التشغيل، ولا تُشارَك بين عدة خوادم (U-15).
- قفل الدخول بكلمة المرور لحساب ما 15 دقيقة بتخمين بريده: مقبول كما في Firebase (المراجعة L-1).
- عدة خوادم (U-15).
- الحماية من مشغّل الخادم نفسه: من يملك القاعدة والمفتاح الرئيسي يملك كل شيء.
