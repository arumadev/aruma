# ADR-018: رابط Realtime Database ونطاقه وشهادته

- الحالة: معتمد
- التاريخ: 2026-10-20
- المرحلة: R0 من Realtime Database (الإصدار 0.2)
- المراجع: [rtdb-decisions.md](../research/rtdb-decisions.md) (Q1)، [rtdb/F-databaseurl-tls.md](../research/rtdb/F-databaseurl-tls.md)، ADR-007، ADR-008
- **يحل محل:**
  - صيغة `databaseURL` المبدئية في ADR-007.
  - البند 1 في ADR-008 («منفذ واحد ونطاق واحد») لمسارات RTDB وحدها.

## السياق

- الصيغة المبدئية في ADR-007 هي `<public_url>/?ns=<project_id>-default-rtdb`. وفحص كود المكتبات الرسمية أظهر أن كل صيغة فيها `?ns=` تنكسر على مكتبة رسمية واحدة على الأقل:
  - **iOS** على نطاق من ثلاثة أجزاء يأخذ الجزء الأول ويتجاهل `ns` (`FUtilities.m:184`).
  - **Admin Go** يستعمل الرابط أساسًا كما هو (`db/db.go:125`).
  - **Admin Python** يُسقط المسار والمعاملات (`db.py:813`).
  - **مكتبة Unity/C++** لا تعرف `ns`.
- **وما يعمل في كل المكتبات** أن يكون اسم القاعدة أول جزء من النطاق. وهذا شكل Firebase نفسه: `<ns>.firebaseio.com`، و`<ns>.<region>.firebasedatabase.app`.

## القرار

1. **الرابط:** `https://<project_id>-default-rtdb.<rtdb.domain>`.
   - `rtdb.domain` إعداد جديد، ومتغيره `ARUMA_RTDB_DOMAIN`.
   - المقترح في الدليل: نطاق فرعي مخصص مثل `rtdb.example.com`، فيكون الرابط من أربعة أجزاء.
   - ونطاق ثنائي مثل `example-db.com` يصلح أيضًا.
2. **بلا `rtdb.domain`:** يبقى رابط التطوير `<public_url>/?ns=<project_id>-default-rtdb`.
   - يعمل على `http://127.0.0.1:<port>` في الويب وAndroid وiOS وJava وPython.
   - إن كان `public_url` على https بلا `rtdb.domain`، يحذّر الخادم عند الإقلاع.
3. **الخادم يحدد القاعدة هكذا:**
   - من أول جزء في `Host`، إن انتهى النطاق بـ `rtdb.domain`.
   - وإلا من `?ns=`، على المدخل الرئيسي فقط.
   - إن وُجد الاثنان واختلفا: 400.
   - الأسماء التي تبدأ بـ `s-` محجوزة، لأن المكتبات تحفظها في الذاكرة المؤقتة.
   - وفي المصافحة يرسل الخادم في `h` النطاق الذي اتصل به العميل.
4. **التوجيه:** الطلب إلى `*.<rtdb.domain>` يذهب كله إلى RTDB قبل التوجيه بالمسار. وعلى المدخل الرئيسي يذهب إلى RTDB `/.ws` و`/.lp`، والطلب الذي فيه `?ns=` وينتهي مساره بـ `.json`.
5. **الشهادة: لا شهادة wildcard.** الدليل يشرح:
   - سجل DNS عام واحد `*.<rtdb.domain>`.
   - Caddy مع `on_demand_tls`، و`ask` يشير إلى Aruma.
   - **نقطة `ask`:** `GET /rtdb/tls-ask?domain=<name>` على العنوان الخاص (`metrics_listen`)، لا على المدخل العام. ترد 200 إن كان الاسم قاعدة مشروع موجود، وإلا 404.
   - ومن يملك مفتاح API لـ DNS يستطيع إصدار شهادة wildcard بنفسه، والخادم لا يفرق.

## البدائل المرفوضة

- **`<public_url>/?ns=…`:** تنكسر على iOS (ثلاثة أجزاء) وAdmin Go وAdmin Python وUnity.
- **مسار لكل قاعدة (`/rtdb/<ns>`):** مكتبة الويب ترفض المسار غير الجذري، وكذلك Admin Java.
- **شهادة wildcard مطلوبة:** تحتاج تحقق DNS-01 ومفتاح API من مزوّد الـ DNS، فتثقل التثبيت. تبقى خيارًا للمشغّل لا شرطًا.
- **منفذ لكل قاعدة:** لا يتسع، ويحتاج فتح منافذ كثيرة.

## العواقب

- **المشغّل يضيف سجل DNS واحدًا.** ومن يستعمل Caddy يضيف كتلة `on_demand_tls`.
- **خلف وكيل Cloudflare:** الشهادة المجانية تغطي مستوى فرعيًا واحدًا. فالنطاق الرباعي يكون بلا الوكيل (DNS only)، أو يُختار نطاق ثنائي.
- **أول اتصال بكل اسم** ينتظر ثواني حتى تصدر الشهادة، ومهلة المكتبات 30 ثانية.
- **حدود Let's Encrypt** تنطبق: 50 شهادة جديدة لكل نطاق مسجّل في 7 أيام.
- **ملفات الإعداد المولّدة** تتغير صيغة `databaseURL` فيها. ولا تطبيق يعتمد عليها قبل 0.2.
- **Admin Go محليًا:** (تحديث R7) صيغة `?ns=` أو `FIREBASE_DATABASE_EMULATOR_HOST` تضع Admin Go وAdmin Node في وضع المحاكي فيرسلان الرمز `owner`، وAruma لا يقبله. فمكتبات Admin تحتاج الرابط الإنتاجي على https، ومحليًا خلف Caddy (`test/experiments/rtdb-caddy.sh`). انظر `docs/guides/rtdb.md`.
