# ADR-016: لغات مكتبة التحقق من رموز Aruma

- الحالة: معتمد
- التاريخ: 2026-10-20
- المرحلة: بين الإصدار 0.1 (Auth) وRealtime Database (القرار F1)
- المراجع: ADR-004، ADR-013

## السياق

خادم المطوّر يتحقق من رمز دخول المستخدم قبل أن يثق به. مكتبة Firebase Admin الرسمية ترفض رموز Aruma، لأن مُصدِرها ومفاتيحها ليست من Google (ADR-004). لذلك يقدّم Aruma مكتبة تحقق بديلة، والسطر الذي يغيّره المطوّر هو الاستيراد (ADR-013).

المكتبة موجودة اليوم بلغتين:
- `@aruma/admin-auth` لـ Node.
- `sdk/go/adminauth` لـ Go.

ولكل منهما اختبارات حية بجانب firebase-admin الرسمي، واختبار العبث `tamper-libs` في CI.

والسؤال: هل نضيف لغات أخرى قبل الخدمات القادمة، مثل Python وJava و.NET وPHP؟

## القرار

- **نبقى على Node وGo** في الإصدارات القادمة.
- **نضيف لغة حين يطلبها مطوّر فعلًا**، بالمعيار نفسه: اختبارات حية بجانب مكتبة Firebase Admin الرسمية لتلك اللغة، ومكانها في `tamper-libs`.
- **لأي لغة أخرى اليوم:** أي مكتبة OIDC أو JWT عامة تتحقق من رموز Aruma. تجد المفاتيح عبر مستند الاكتشاف `<iss>/.well-known/openid-configuration`، والتوقيع RS256 (ADR-004).

## البدائل المرفوضة

- **أربع لغات أو أكثر الآن:** كل مكتبة عقد يجب أن يبقى مطابقًا لسلوك firebase-admin، ويُختبر ضد العبث، ويُصان مع كل تغيير في الرموز. هذه كلفة دائمة بلا طلب.
- **مكتبة واحدة بلغة واحدة:** Go وNode هما لغتا الخوادم الأكثر استخدامًا مع Firebase Admin، ولكل منهما مكتبة رسمية نقارن بها.

## العواقب

- مطوّر Python أو Java يكتب سطور تحقق أكثر من سطر الاستيراد. ويحتاج دليل Admin مثالًا قصيرًا بمكتبة OIDC عامة.
- إضافة لغة لاحقًا لا تحتاج تغييرًا في الخادم، فالعقد كله في ADR-004.
