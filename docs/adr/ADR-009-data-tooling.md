# ADR-009: أدوات البيانات

- الحالة: معتمد
- التاريخ: 2026-10-18
- المرحلة: 1

## السياق

Aruma خادم واحد فوق قاعدة Postgres واحدة (U-12، U-15). كل خدمة تأخذ قسمًا (schema) خاصًا بها، والمراحل القادمة تضيف أقسامًا جديدة. نحتاج طريقة للوصول إلى البيانات تُبقي SQL ظاهرًا وقابلًا للمراجعة، ومخططًا لا يتغيّر إلا بأمر صريح من المشغّل.

## القرار

1. **المشغّل:** `github.com/jackc/pgx/v5` مع `pgxpool`، بلا ORM.
2. **الاستعلامات:** sqlc يولّد كودًا ذا أنواع ثابتة من ملفات SQL. الكود المولَّد يُحفظ في المستودع، وCI يعيد التوليد ويفشل إن ظهر فرق.
   - يُشغَّل بـ `go run github.com/sqlc-dev/sqlc/cmd/sqlc@<version>` من `Makefile`. لا يدخل في `go.mod`، لأن محلّل Postgres فيه يعتمد على cgo ويثقل البناء.
3. **الـ migrations:** goose بملفات SQL مرقّمة، في مجلد لكل قسم تحت `internal/store/migrations/<schema>/`. ولكل قسم جدول إصدار مستقل `public.goose_<schema>`، فيُرقَّم كل قسم وحده.
   - تُضمَّن في الثنائي بـ `embed`، ويطبّقها `aruma migrate up` فقط.
   - **`aruma serve` لا ينفّذ DDL أبدًا.** يقرأ الإصدار عند الإقلاع، ويرفض العمل إن كان المخطط متأخرًا.
   - للأمام فقط في الإنتاج. ملفات `Down` موجودة للتطوير، والتراجع في الإنتاج يكون بالنسخة الاحتياطية.
4. **المفاتيح:** كل جدول في قسم خدمة بيانات يبدأ مفتاحه بـ `project_number`. وكل استعلام على جدول مرتبط بمشروع يأخذ `project_number` شرطًا، ويفحص ذلك اختبار في CI.
5. **المعرّفات الداخلية:** `uuidv7()` المضمّنة في Postgres 18، فتُرتَّب زمنيًا دون امتداد إضافي.
6. **المهام الخلفية:** `river` عند أول حاجة حقيقية، لا في هذه المرحلة.
7. **إصدار Postgres:** الأدنى 18، لأننا نعتمد على `uuidv7()`. والاختبار على 18.1 محليًا.
8. **الاختبارات:** على Postgres المحلي، بقاعدة جديدة لكل حزمة اختبار تُنشأ وتُحذف تلقائيًا، بلا Docker. في CI يعمل Postgres 18 كخدمة.

## البدائل المرفوضة

- **ORM (مثل GORM أو ent):** يخفي SQL ويصعّب فرض شرط `project_number` على كل استعلام.
- **migrations يطبّقها الخادم عند الإقلاع:** تشغّل DDL ضمن مسار الخدمة، وتتسابق عند إعادة التشغيل.
- **مجلد migrations واحد لكل الأقسام:** يربط ترقيم الخدمات ببعضها، ويمنع إضافة قسم جديد دون المساس بتسلسل الآخرين.

## العواقب

- إضافة استعلام تعني ملف SQL ثم `make sqlc`.
- كل قسم جديد يحتاج سطرًا في `migrations.Schemas`.
- النشر يتطلب خطوة `aruma migrate up` قبل تشغيل الإصدار الجديد.
