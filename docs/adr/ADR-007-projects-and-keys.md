# ADR-007: المشاريع والمفاتيح والمعرّفات

- الحالة: معتمد مبدئيًا. يُجمَّد بعد نجاح اختبارات الدخان (T21).
- التاريخ: 2026-10-18
- المرحلة: 1
- المراجع: [docs/research/client-config-formats.md](../research/client-config-formats.md)، [docs/research/management-api.md](../research/management-api.md)

## السياق

ملفات الإعداد التي يوزّعها المطوّرون تحمل هذه المعرّفات داخل تطبيقاتهم المنشورة. أي صيغة خاطئة تُكتشف بعد التوزيع لا يمكن تصحيحها دون كسر تلك التطبيقات. لذلك تُحسم الصيغ هنا، وتُختبر على المكتبات الرسمية قبل التجميد.

## القرار

### العزل

- قسم `control` يحمل المشاريع وما يتبعها. وكل قسم لخدمة بيانات (من المرحلة 2) يضع `project_number` أول عمود في مفتاح كل جدول.
- تُحجز محاور التوسّع `tenant_id` و`database_id` و`instance` و`bucket`، ولا تُبنى الآن.

### المعرّفات

| المعرّف | الصيغة | المصدر والسبب |
|---|---|---|
| `project_id` | `^[a-z][a-z0-9-]{4,28}[a-z0-9]$` (6 إلى 30)، ثابت، لا يُعاد استعماله بعد الحذف | يدخل في المسارات وأسماء الحسابات |
| `project_number` | 12 رقمًا عشوائيًا، أولها من 1 إلى 9، يولّده الخادم | يدخل في `appId` و`messagingSenderId` |
| `app_id` | `1:<project_number>:<web\|ios\|android>:<16 hex>` | iOS يشترط 4 أجزاء، والمنصة حرفيًا `ios`، والذيل hex يُقرأ رقمًا بـ 64 بت. 16 حرفًا يملأ 64 بت تمامًا، وتجاوزه غير مضمون |
| `apiKey` | `Aru` + 36 حرفًا من `[A-Za-z0-9_-]` = 39 | Installations على iOS وAndroid يشترط `A` + 38 من هذه الحروف. لا مكتبة تشترط `AIza`، والبادئة الخاصة تحقّق U-17 |
| حساب الخدمة | الاسم `^[a-z][a-z0-9-]{4,28}[a-z0-9]$`، والبريد `<name>@<project_id>.sa.<project_domain>` | بشكل بريد دون نطاق Google |
| `unique_id` | 21 رقمًا، أولها من 1 إلى 9 | شكل `client_id` في ملف المفتاح |
| `private_key_id` | 40 حرفًا hex | يُرسل `kid` في رأس JWT |
| `etag` | `1_<uuid>` يتجدد مع كل تعديل | الشكل الملاحَظ في الردود الحقيقية |

- مفتاح API **واحد لكل منصة في كل مشروع**: كل تطبيقات Android في المشروع تشترك في مفتاح، وكذلك iOS والويب. يُنشأ عند أول تطبيق لتلك المنصة.
- مفتاح API ليس سرًا ولا هوية. يُخزَّن كما هو، ولا يمنح أي صلاحية إدارية.

### الحقول المشتقة في ملفات الإعداد

`project_domain` يأتي من الإعداد، وافتراضيًا هو مضيف `public_url`.

| الحقل | القيمة |
|---|---|
| `messagingSenderId` | `project_number` |
| `authDomain` | `project_domain`، وقابل للتعديل لكل مشروع. لا يتطلب DNS بدلًا (wildcard)، لأن صفحات المصادقة تعرف المشروع من مفتاح API |
| `storageBucket` | `<project_id>.<project_domain>`. اسم فقط، لا يحتاج DNS |
| `databaseURL` | `<public_url>/?ns=<project_id>-default-rtdb`. **مبدئي**، يُثبَّت في المرحلة 3 |
| `resources.hostingSite` | `project_id`. يُملأ دائمًا حتى لا تستدعي أداة `firebase` واجهة Hosting عند إنشاء تطبيق ويب |
| `locationId` | لا يُرسل |

### الحذف

- حذف المشروع أو التطبيق مؤجّل 30 يومًا (`state = DELETED`، و`expire_time`)، ويمكن الاسترجاع خلالها.
- `project_id` يبقى محجوزًا بعد الحذف النهائي.
- `package_name` و`bundle_id` ثابتان بعد الإنشاء، ويفرض ذلك trigger في القاعدة.

## البدائل المرفوضة

- **بادئة `AIza`:** تخالف U-17، وتوهم بأن المفتاح صادر عن Google.
- **ذيل hex بطول 22 للويب كما في Firebase:** لا تحتاجه أي مكتبة، وتوحيد الطول يبسّط الفحص.
- **نطاق فرعي لكل مشروع في `authDomain`:** يفرض DNS بدلًا وشهادة wildcard على كل مشغّل.

## العواقب

- اختبارات الدخان (T21) تثبت أن الصيغ مقبولة. بعدها يتحول هذا السجل إلى «مجمّد»، وأي تغيير يحتاج سجلًا جديدًا يشرح الترحيل.
- شكل `databaseURL` قد يتغير في المرحلة 3 قبل أن تعمل قاعدة البيانات اللحظية. لا يكسر ذلك شيئًا، لأن لا مكتبة تستعمله قبل ذلك.
